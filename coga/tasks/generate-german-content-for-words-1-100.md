## Description

Generate the full content for the first 100 words: English translation, meanings, up to 10 example sentences per meaning and at most 20 per entry (spread evenly across meanings) using only forms introduced so far, English translations, and grammar notes the first time a concept appears. This pilot shows whether the approach and quality hold up before scaling.

## Context

Project: German vocabulary course for English speakers, with word frequencies from Tatoeba's German sentences (tatoeba.org, CC BY 2.0 FR; counts only, sentences are newly written). Content is CC BY 4.0, code MIT. Target: 1,000 word forms in learning order (frequency order, adjusted by at most 50 positions so early sentences can be formed); a second 1,000 (words 1,001–2,000) may follow later, possibly as its own PDF. `words.json` keeps 5,000 ranked forms so the course can grow without rebuilding the list. Pilot: first 100 words. Layout: shared Python in `tools/`, data in `german/json/` (one JSON file per word), audio in `german/audio/`, PDF `german/first 1000 german words.pdf`. Later languages (e.g. `french/json/`) mirror the same layout.

- Writes `german/json/entries/00001 …json` through `00100 …json` and updates `german/json/grammar.json`. All entries must pass the sentence checker.
- Each grammar concept introduced here also gets its `examples[]` in grammar.json (target 3, only forms with order ≤ its `first_entry`).
- Expected: the very first words in learning order have almost no prior vocabulary, so early entries will have fewer than 10 sentences. That is acceptable ("if the current body of words permits").
- Decided 2026-11-27: content is generated by a script in `tools/` that calls the Anthropic Messages API, batch by batch, with the sentence checker run per batch and failures fed back for retry. The key comes from the ticket secret `TOWER_ANTHROPIC_KEY`; the script reads that variable and passes it explicitly (`anthropic.Anthropic(api_key=...)`), never the default `ANTHROPIC_API_KEY`, so Coga's `claude` sessions stay on the subscription. Model choice (Opus vs Sonnet, cost vs quality) is settled in the build step on a small sample. Carries into generate-german-content-for-remaining-words.
- Depends on: review-german-word-list, write-sentence-checker.

### Points for the human to judge
1. **Naturalness at the edges.** Flagged odd sentences survive (flag-only): e.g. 51 "Das ist sehr gut mit dir.", 70 "Tom hat uns.", 9 "Es ist nicht er.", 39 "Er ist zu gut, aber ich habe es nicht." Acceptable rate (~3%), or should flagged sentences be auto-dropped/regenerated?
2. **Grammar note placement** isn't code-checked semantically: reviewer caught 74 werden (future note on the wrong sentence) and 54 "da" (subordinate clause, no note). Spot-check a few concepts in grammar.json.
3. **Digits loophole:** checker lets digits pass, so the model wrote "Vor 8 bin ich nicht hier." to avoid an unknown "acht". Forbid digits in prompt (or checker)?
4. **Concept grain** (54 concepts in 100 words): e.g. separate `verb.werden.future` / `verb.werden.plural_infinitive`, `verb.koennen.plural_infinitive`. Too fine?
5. **Pilot verdict:** good enough to scale on Sonnet, or re-run with Opus (`--model claude-opus-5-5 --force`, ~$3–4)? Cost savings for 5k are deferred (see above).
